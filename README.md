# Trading-Agent-CN

**A股 AI 多智能体投研助手** —— 7 个 LLM 智能体分工协作，从基本面、技术面、消息面、资金面四个角度分析个股，经多空辩论和风控审查后，给出带完整理由链的决策建议。

电脑和手机都能用：一套响应式 Web + PWA，手机可"添加到主屏幕"像 App 一样打开。

> ⚠️ **本工具输出由 AI 生成，仅供研究参考，不构成投资建议。** 模型可能产生事实性错误，数据源可能延迟或错漏。证券投资存在本金损失风险，请独立决策并自行承担后果。

## 快速开始

```bash
git clone <本仓库>
cd Trading-Agent-CN-

# 1. 安装依赖并生成 .env
make setup

# 2. 直接启动 —— 此时是离线桩模式，不需要任何 API Key
make dev
```

打开 <http://localhost:3000>，整条链路（数据 → 智能体 → 决策 → 界面）立刻可跑。

> **Windows 用户**：`make` 命令默认不存在，请按
> [docs/SETUP-Windows.md](docs/SETUP-Windows.md) 走 Docker 方案（更省事）。

**离线桩模式**下用的是模板化的占位分析和程序生成的模拟行情，**结论无任何参考价值**，作用是让你先看清系统长什么样。要跑真实分析，编辑 `.env`：

```bash
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...          # https://console.anthropic.com
DATA_PROVIDER_ORDER=akshare,tushare   # AKShare 免费免注册，够用
```

重启后端即可。Docker 用户可以直接 `make docker`。

### 在手机上用

1. 确保手机和电脑连的是同一个 Wi-Fi
2. 查到电脑的局域网 IP（Windows 用 `ipconfig`，Mac/Linux 用 `ifconfig`）
3. 手机浏览器打开 `http://<电脑IP>:3000`，例如 `http://192.168.1.8:3000`
4. **iPhone**：Safari → 分享 → 添加到主屏幕　**Android**：Chrome → 菜单 → 安装应用

装好后全屏运行，和原生 App 观感一致。

> 不需要改 `CORS_ORIGINS`。浏览器只访问前端（`:3000`），由 Next 在**服务端**
> 代理到后端，浏览器从不直接请求 `:8000`，因此不涉及跨域。
> Windows 用户可能需要在防火墙里放行 3000 端口，见
> [docs/SETUP-Windows.md](docs/SETUP-Windows.md)。

## 它是怎么工作的

```
       用户输入股票代码 + 分析周期（短线/波段/中线）
                        │
                        ▼
        ┌───────────── 数据层 ─────────────┐
        │  AKShare ─┬─ 行情/K线/财报/新闻/资金流  │
        │  Tushare ─┘  （逐接口自动降级）          │
        └───────────────┬──────────────────┘
                        ▼
              渲染成统一的中文行情简报
           （所有智能体共享，命中提示缓存）
                        │
    ┌───────────────────▼───────────────────┐
    │ 第一阶段：四位分析师并发                 │
    │  基本面 │ 技术面 │ 消息面 │ 资金面        │
    └───────────────────┬───────────────────┘
                        ▼
    ┌───────────────────────────────────────┐
    │ 第二阶段：多空辩论（默认 2 轮，互相看得到对方）│
    │  多头研究员 ⇄ 空头研究员                  │
    └───────────────────┬───────────────────┘
                        ▼
    ┌───────────────────────────────────────┐
    │ 第三阶段：风控经理                        │
    │  波动/流动性/规则风险 → 仓位上限 + 止损方案  │
    └───────────────────┬───────────────────┘
                        ▼
    ┌───────────────────────────────────────┐
    │ 第四阶段：交易决策员（结构化 JSON 输出）      │
    │  操作 / 信心度 / 仓位 / 进出价位 / 理由 / 风险 │
    └───────────────────────────────────────┘
```

整个过程通过 SSE 实时推给前端，你能看到每个智能体逐字产出，而不是干等几分钟。

**手机友好的关键设计**：分析任务在服务端独立运行，与前端连接解耦。锁屏、切 App、地铁断网都不会让这次分析白跑 —— 重新连上时会从断点续传（`Last-Event-ID`），连接彻底失败则自动降级为轮询读取落库结果。

## 设计要点

### 数据源逐接口降级
两个数据源各有短板：AKShare 免费但偶发失败，Tushare 稳定但要积分、且**没有个股新闻接口**。所以降级是按**单个接口**做的，不是整体切换：

```
DATA_PROVIDER_ORDER=tushare,akshare
  → 行情/K线/财报 走 Tushare（规范稳定）
  → 新闻/资金流 自动落到 AKShare（Tushare 不支持）
```

每次分析的结果里都会带上 `data_sources`，明确告诉你每个维度的数据实际来自哪儿。

### 实时价格：节奏由交易时段决定
盘中每 5 秒刷新，集合竞价 15 秒，午间休市和收盘后**完全不刷** —— 收盘后每 5 秒拉一次价格毫无意义，既浪费请求，也会把免费数据源打得更快挂掉。节奏来自 `GET /market/session`，前端不自己写死交易时间。

切到后台立即暂停，回到前台立刻补一次（手机上 PWA 切走还在轮询纯属耗电）。请求失败时指数退避，并且**保留上次的价格**、只标注刷新失败 —— 数据源抖一下就白屏是最糟的体验。

时段判断用固定 UTC+8，不依赖容器的 `TZ` 环境变量：`TZ=Asia/Shanghai` 需要系统装了 tzdata，`python:3.11-slim` 这类镜像未必有，缺了会**静默**回落到 UTC，差 8 小时且毫无报错。

> 未计入法定节假日（完整交易日历需要外部数据）。节假日会被当作交易日，后果只是多轮询几次、价格不变；反过来漏判交易日才严重，所以这里刻意宁松不严。

### 按名称搜索靠本地代码目录
按名称搜索需要全市场代码表。最初每次搜索都现场去问数据源，于是数据源慢或挂的时候，输入"茅台"会一直卡在「搜索中」—— AKShare 那个全市场接口 5000+ 行，慢或失效都是常态。

现在成功拉到一次就落库（`symbol_directory` 表），之后搜索是纯本地查询（毫秒级），**数据源事后挂掉也照样能搜**。目录在启动后于后台建立，不阻塞任何请求；只增量更新、不整表替换，一次拉漏了不会把好数据删掉。

输入合法 6 位代码时还有第三层保障：代码规范化是纯本地计算，不依赖任何数据源，永远能进详情页。

### 备份数据源：主机互不相同
`push2*.eastmoney.com` 这一组主机在部分网络下不可达（代理软件、公司网络、个别运营商线路），而同域名下的 `search-api-web.eastmoney.com` 却是通的 —— 换浏览器 TLS 指纹也救不回来，因为问题在主机而不在客户端。

所以除了 AKShare（东方财富），还内置了两个**和东方财富没有任何共用主机**的源：

| 数据源 | 提供 | 主机 |
| --- | --- | --- |
| `akshare` | 全部维度，字段最全 | `push2*.eastmoney.com` |
| `xueqiu` | 实时行情（一个请求带齐价格/估值/市值）| `xueqiu.com` |
| `sina` | 日线、大盘指数、全市场列表（建代码目录用）| `*.sina.com.cn` |
| `tushare` | 行情、日线、财报等（需免费 token）| `api.tushare.pro` |

默认顺序 `akshare,xueqiu,sina,tushare`。降级是按接口做的，所以可以出现"行情走雪球、K线走新浪、新闻走东财"这种组合，`active_sources` 会如实报出每个维度的实际来源。

设置页的诊断还会**对每个主机用普通 requests 和浏览器指纹各打一次**，据此区分"连不上这个域名"和"客户端被按指纹拒绝"—— 这两者的处理方式完全不同，而光看接口报错是分不清的。

### 实时价拿不到时，用收盘价兜底 —— 但必须标明
真实场景里会出现"K线是真的、只有最新价拿不到"（日线走新浪通着，而所有实时行情接口都不通）。这时候直接报错的话整个界面没有价格、分析也跑不起来，而最近一根日线的收盘价是**完全真实**的数据 —— 收盘后它本来就等于现价。

所以实时接口全失败时会退到最近一根日线，并且：

- Quote 上带 `is_realtime=false` 和 `quote_date`；
- 界面显著标注「收盘价 · X月X日（非实时）」，并说明实时接口不可用；
- 盘中时段徽标从「5 秒自动刷新」改成「每 5 秒重试实时接口」—— 否则会让人以为那个数字在跳动，而它其实是个不动的收盘价；
- 给模型的行情简报里写明这不是实时价，并要求它据此降低涉及当前价位判断的置信度、在结论里声明这一前提。

**标注是这件事的重点。** 盘中把上一个交易日的收盘价当现价展示而不告知，比没有价格危险得多 —— 用户会照着它下单。

### 绝不用假数据填充
`DATA_PROVIDER_ORDER` **默认不含 `mock`**。取不到真数据时，界面会明确显示取数失败和失败原因，而不是画出一排看起来很真的数字。

这条是被真事教育出来的：AKShare 的全市场快照接口按每页 100 条翻页，5400 多只股票要翻 54 页，而且 akshare 在每页之间还会 `sleep(0.5~1.5)` —— **单次调用要 60~90 秒**，在任何合理的请求超时下都必然失败。于是每次都静默降级到 mock，界面上出现"华宝股份 299.42"，AI 还基于这个假价格给出了一整套止盈止损点位，看起来跟真的完全一样。

两处修正：
- **单只行情不再走全市场快照**，改用 `stock_bid_ask_em`（单只、单请求、不翻页不睡眠），估值另取 `stock_value_em`（日频，按小时缓存并按当前价折算）。
- **全市场列表只在后台跑**，用单独的大超时（`SYMBOL_INDEX_TIMEOUT`，默认 240 秒）建本地代码目录；请求侧查的是本地表，毫秒级。

`mock` 仍然保留，但必须显式写 `DATA_PROVIDER_ORDER=mock` 才会启用，用途只有一个：不联网时看看界面长什么样。配置里一个可用数据源都没有时（比如把 `akshare` 拼成了 `akshre`），服务会**直接启动失败**，而不是悄悄回落到假数据。

### 数据缺失绝不隐瞒
某个维度抓取失败时，行情简报里会明确写「⚠️ 财务数据缺失」，并要求相关分析师在结论中声明受此限制。**不会让模型对着空数据编结论**。用了 mock 数据时更会在简报里大字标注，要求模型在输出开头就声明。

### 成本优化：共享提示缓存
一次分析里 7 个智能体读的是同一份行情简报（约 2000+ token）。简报被放在 `system_blocks[0]` 并打上 `cache_control` 断点，后续智能体全部命中缓存 —— 顺序不能颠倒，否则前缀各不相同，缓存全部失效。

### 模型可替换
默认 Claude（`claude-opus-5`，开启自适应思考与拒答兜底）。分析师可单独配便宜的模型（`ANTHROPIC_ANALYST_MODEL=claude-sonnet-5`）来省钱，决策环节仍用主模型。国内网络不便直连时，可切到 DeepSeek / 通义千问 / Kimi 等 OpenAI 兼容接口：

```bash
LLM_PROVIDER=openai_compat
OPENAI_COMPAT_BASE_URL=https://api.deepseek.com/v1
OPENAI_COMPAT_API_KEY=sk-...
OPENAI_COMPAT_MODEL=deepseek-chat
```

### 分析深度：按次选，按厂商翻译

分析页可以按次选「快速 / 标准 / 深度」，而不是只能用 `.env` 里的全局配置。
对外只暴露档位、不直接给 effort 滑块，是因为各家能调的东西不一样 ——
DeepSeek 等兼容接口根本没有 effort 参数，给个滑块也是假开关：

| 档位 | 辩论轮数 | 调用次数（默认配置） | Claude | DeepSeek 等兼容接口 |
| --- | --- | --- | --- | --- |
| 快速 | min(1, N) | 8 | 推理投入下调两档 / 一档 | 只少辩论 |
| 标准 | `DEBATE_ROUNDS` | 10 | `LLM_EFFORT` | 主模型 |
| 深度 | N + 1 | 12 | 推理投入上调一档 / 两档 | 风控与决策改用 `OPENAI_COMPAT_REASONING_MODEL` |

- **标准档和之前的行为完全一致**，不改任何配置结果不变。
- 每一档具体改了什么由后端按当前配置生成（`GET /api/v1/analysis/options`），前端不写死。
- 「高级」里可以手选模型，但只接受白名单（已配置的模型 + `LLM_MODEL_CHOICES`）。
- 每次分析的档位、模型、推理投入都会落库，回看历史时能分清结论差异来自行情还是档位。
- 决策这一步换过模型（推理模型、手选模型）却没拿到可解析的决策时，自动用主模型重做一次，并在决策面板上注明。

### 场内 ETF：同一套界面，不同的数据和分析框架

512480（半导体ETF）、512400（有色金属ETF）这类场内 ETF 可以和股票一样搜索、
加自选、看实时价和 K 线、跑分析。沪市 51/52/56/58 开头、深市 159 开头的代码
会被识别成 ETF（LOF 和封闭式基金暂不支持，会明确报错而不是当成股票去查）。

ETF 和个股在每一层都不一样，所以不是"把代码放行"就完事：

| | 股票 | ETF |
| --- | --- | --- |
| 实时价 | 东财盘口 → 雪球 → Tushare | 东财盘口（仅深市 159）→ 雪球 → 新浪（一个请求拿全部 ETF）。东财盘口会把 5 开头的沪市 ETF 查成深市，所以沪市直接跳过 |
| 日线 | 东财 → 新浪 → Tushare | 东财 ETF 日线（前复权）→ 新浪（不复权，遇到份额折算的价格断层只保留断层之后的数据） |
| 基本面 | 财报 + 市盈率 / 市净率 | 跟踪标的、规模、费率 + 前十大重仓股（天天基金档案） |
| 新闻 | 按代码搜 | 按板块关键词搜（"半导体ETF" → "半导体"），按代码几乎搜不到 |
| 价格精度 | 0.01 元 | 0.001 元（界面、K 线、斐波那契价位、给模型的简报都按三位小数） |
| 交易制度 | T+1 | 股票类 T+1；跨境 / 债券 / 黄金 / 货币 ETF 为 T+0，按名称初判并写进简报 |

股票和 ETF 在数据层是两组能力标识（`quote` / `etf_quote` 等），registry 不会把 ETF
派给只会查股票的源；报错里也会如实写"未声明支持 etf_quote"，而不是一个莫名其妙的空结果。
分析时基本面分析师换一套 ETF 专用提示词，简报里加一节「本标的是 ETF：分析要点」。

### 斐波那契回撤

自动斐波那契：取最近 60 个交易日的最高/最低价作摆动端点，按两者的**先后顺序**
判定方向 —— 低点在前是上涨段（回撤位在高点下方，是支撑），高点在前是下跌段
（回撤位在低点上方，是阻力）。方向判反的话支撑阻力会完全颠倒，所以测试里专门
锁了这一条。

给出 23.6% / 38.2% / 50% / 61.8% / 78.6% 回撤位，以及 127.2% / 161.8% / 261.8%
扩展目标位。技术面分析师的提示词里明确要求它注意方向，并在多个依据重合时
（如 MA60 与 61.8% 位）特别点出 —— 这种共振位的有效性通常更高。

图上只叠加回撤位和摆动端点（扩展位远在数据区间之外，画上去会把纵轴压扁），
并且只给摆动端点和紧贴现价的那两条打价格轴标签，避免 7 个标签在手机上糊成一片。

一个需要知道的性质：因为端点取的就是窗口极值，回撤率恒在 0-100% 之间，
不会出现"跌破斐波那契区间"。判断突破要看 60 日新高/新低相关字段。

### A股规则内建
- 代码规范化覆盖沪/深/北全部板块，各家数据源格式自动转换（`600519` / `sh600519` / `600519.SH` 都认）
- 涨跌幅限制按板块区分（主板 ±10%、创业板/科创板 ±20%、北交所 ±30%），风控据此推导止损距离
- T+1 制度写进提示词，决策必须在此约束下可执行
- 界面**红涨绿跌**（照搬欧美的绿涨红跌会让用户完全看反）

## 项目结构

```
backend/
  app/
    core/          配置、日志、领域异常
    data/          数据源适配器（akshare / tushare / mock）+ 降级路由 + 代码规范化
    llm/           模型抽象层（anthropic / openai 兼容 / 离线桩）
    agents/        角色提示词、上下文渲染、流水线编排
    services/      技术指标、快照组装、分析任务、SSE 事件缓冲
    api/v1/        HTTP 接口
    db/            SQLAlchemy 模型与会话
  tests/           89 个测试，全部离线跑（不联网、不花钱）

frontend/
  src/
    app/           页面（自选 / 分析 / 历史 / 设置）
    components/    外壳、智能体卡片、决策面板、K线图、搜索
    lib/           API 客户端、SSE Hook、格式化
  public/          PWA manifest、Service Worker、图标
```

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/status` | 数据源健康状况、当前模型、进行中的任务 |
| GET | `/api/v1/market/search?q=` | 按代码或名称搜索（本地目录 → 数据源 → 代码直达三层保障）|
| GET | `/api/v1/market/session` | 当前交易时段与建议轮询间隔 |
| GET | `/api/v1/market/quotes?symbols=` | 批量行情（自选股轮询用，一次最多 50 只）|

## 当前边界

这是一个**投研分析**工具，不是交易系统。明确**不包含**：

- **实盘下单**。A股散户拿不到公开下单 API（需券商 QMT/PTrade 等），本项目不碰资金操作。
- **市盈率等估值指标的实时性**。估值来自日频的估值表（按当前价做了比例折算），不是逐笔计算的。
- **逐笔/分时行情与盘口**。实时价格是按秒级轮询数据源快照，不是行情推送（Level-1 快照本身就有 3 秒粒度），也没有五档盘口和分时图。要做这些得接券商行情网关。
- **策略回测**。指标计算已经有了（`services/indicators.py` 是纯函数，易于复用），但没有回测引擎。
- **多用户与鉴权**。当前是单人本地工具，`watchlist` 表没有 `user_id`。要做多用户需加鉴权和数据隔离。
- **ETF 的折溢价与份额变化**。IOPV 实时估值和份额申赎数据需要翻页拉全市场表，
  还没接入；简报里会让模型如实说明"无法判断折溢价"。LOF、封闭式基金也暂不支持。
- **多进程部署**。SSE 事件缓冲和行情缓存都在进程内存里，多 worker 会导致断线重连失败。需换 Redis（`services/run_store.py` 和 `data/cache.py` 的接口已为此预留）。

后续规划见 [docs/ROADMAP.md](docs/ROADMAP.md)，架构细节见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。
