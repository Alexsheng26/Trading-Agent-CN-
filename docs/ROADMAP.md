# 后续规划

按"能立刻用上"到"需要较大改动"排列。当前版本是框架，下面这些是明确留了扩展点的方向。

## 近期（扩展点已就位）

### 自选股批量扫描
现在只能一只一只分析。加一个"扫描全部自选股"：并发跑 N 个分析，
出一张按信心度排序的表。`AnalysisService.start()` 已经是异步任务模型，
加一层批量调度即可。注意并发要限流，否则会打爆数据源和模型速率限制。

### 条件触发提醒
自选股满足条件时推送（放量突破、跌破 MA60、主力连续流出）。
`services/indicators.py` 的形态标签已经能算出这些，缺的是：
- 定时任务（APScheduler 或系统 cron 调 API）
- 推送通道（PWA 已装 Service Worker，加 Web Push 即可；或走企业微信/钉钉机器人）

### 行业与同业对比
分析师现在只看单只票。加一个"同行业可比公司"维度，
让基本面分析师能判断"ROE 20% 在这个行业算高还是低"。
AKShare 有行业成分股接口，`DataProvider` 加一个 `industry_peers` 能力即可。

### 分析结果导出
导出成 Markdown / PDF 存档。后端已经把完整产出落库（`agent_outputs` 表），
加一个导出接口即可。

## 中期（需要新模块）

### 策略回测
指标计算已经是纯函数（不依赖 pandas，易于复用），但没有回测引擎。
要做的话建议独立成 `app/backtest/`：
- 事件驱动的撮合循环，**必须处理 A股特有规则**：T+1、涨跌停不能成交、停牌、
  除权除息（用前复权数据可回避部分问题）
- 绩效指标：年化收益、最大回撤、夏普、胜率、盈亏比
- 注意别做成"用未来数据调参"的自欺工具 —— 样本内外要分开

### 多用户
当前是单人本地工具，`watchlist` 表没有 `user_id`。要做多用户：
1. `watchlist` / `analysis_runs` 加 `user_id` 列和索引
2. 加鉴权（本地工具建议简单的单密码或 OAuth，别自己实现密码哈希）
3. 每用户的模型调用配额与限流

### 多进程部署
见 [ARCHITECTURE.md](ARCHITECTURE.md#单进程限制与扩展路径)。
把 `RunStore` 换成 Redis Streams、`TTLCache` 换成 Redis，两者接口都已预留。

### 提示词评测
智能体的输出质量目前靠人看。要系统化改进提示词，需要一套评测集：
固定一批历史时点 + 标的，跑同一套提示词，比较输出的一致性与合理性。
注意**不能用"事后涨没涨"当唯一标准** —— 那是在训练模型做后验归因，
而不是评估分析质量。

## 明确不做

### 实盘下单
A股散户拿不到公开下单 API（需券商 QMT/PTrade 等机构渠道）。
用 `easytrader` 之类的模拟点击方案既不稳定、也有账户安全和合规风险。
本项目定位是投研辅助，不碰资金操作。

若确实需要，正确做法是：
- 抽象一个 `ExecutionProvider` 接口，先实现纸上交易（模拟撮合）
- 真实下单由用户自己对接持牌券商的正规接口，且必须有人工二次确认环节
- 永远不要让 LLM 的输出直接触发下单

### 荐股 / 收益承诺
提示词里明确禁止"保证""稳赚""必涨"类表述，界面常驻免责声明。
这不是可以放宽的产品选项。
